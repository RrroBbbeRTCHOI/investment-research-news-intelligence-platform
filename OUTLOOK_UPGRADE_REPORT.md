## Architecture

Perigon → existing normalization/dedupe/pending → frozen prefilter → additive live classifier:

- Event-intelligence route → existing budgeted Gemini/cache and frozen research pipeline.
- Outlook → deterministic source extraction → completed Outlook record, zero Gemini.
- Skip → remove pending, retain seen identity, no research record and zero Gemini.

Existing state saving, cursor advancement, quota reservation, locks, pending handling, provider boundaries and atomic snapshot writing remain in place. The snapshot has mixed `articles`; Flask still only reads files. Browser polling cannot call ingestion or Gemini.

## Decision rules

Frozen explicit reject and hard entertainment/sports exclusions win. Affirmative current/result wording in the headline wins over preview background. Modal/negated action wording is not affirmative evidence. Future wording plus an explicit research catalyst routes to Outlook; generic preview/company name alone does not establish an Outlook catalyst. Remaining decisions delegate to the unchanged V3.2.2 intake gate.

Examples verified:

| Headline | Route |
|---|---|

Compatibility distinction: `content_type=event` identifies the existing event-intelligence processing lane; it does **not override** the frozen final `gate.is_event`. Previously accepted commentary (including frozen ST11) remains accepted with its original classification. Thus not every legacy event-lane record is asserted to be a discrete event. This deliberate compatibility limit preserves the requested V3.2.2 behavior; the final gate remains visible in Audit.

## Outlook schema and evidence

`content_type: outlook`; `outlook` includes `status`, `category`, `catalysts`, `scheduled_at_utc`, `expected_window`, `watch_reasons`, `related_tickers`, `related_macro_topics`, `source_basis`, `method`, `notice`.

Categories are earnings, company_event, macro_data, monetary_policy, regulatory, semiconductor_supply, geopolitical_watch, other_research_outlook. Source evidence contains field, exact quote, start and end offsets. A MAG7 ticker is related only when explicitly adjacent to a reporting/earnings catalyst in headline or summary, labeled `direct_catalyst_subject`; this is not exposure qualification. Broad mentions are not promoted. Why Watch is source-extractive, not an invented investment conclusion.

Dates: only an explicitly scheduled, timezone-qualified ISO timestamp in the source is resolved. Thursday/next week remains an unresolved source window. No guessed calendar date or company-HQ geography. Outlook has `event=null`, `geography=null`, empty ticker_analysis and candidate_channels, `gate.is_event=false`, and severity `N/A — Upcoming` with null score.

## Outlook scores

Event scores are unchanged. Outlook relevance is a transparent new product heuristic:

- Macro/monetary context: 60 points.
- Earnings/company/regulatory/semiconductor/geopolitical catalyst context: 55 points.
- Other supported Outlook context: 40 points.
- Explicit direct watchlist catalyst subject: +15 points.

Watch Priority = Outlook Relevance + 10 only when a resolved future timestamp falls within 168 hours of snapshot generation; otherwise no timing bonus. High ≥75, Medium ≥50, Low <50. Components and method names are exposed in Audit. These are uncalibrated attention policies, not event severity, probabilities, returns or direction. Local portfolio matches are separately displayed and do not alter shared scores. No event urgency is supplied for Outlook.

## Limits and use

This is bounded English pattern extraction, not universal semantic classification. Headline/result recognition and catalyst coverage are intentionally conservative; future wording in body-only material may remain governed by legacy intake. Existing final gate remains authoritative. Old completed records are not reprocessed; old skipped identities remain seen. Outlook windows are source claims, not a verified economic calendar. Upcoming status is not automatically converted into an occurred event or expired record; time-based scores use the snapshot timestamp. Why Watch is extractive and may repeat the headline. No new LLM architecture or financial methodology was added.

Unzip this separate folder and use its existing requirements/startup workflow. Supply your local environment settings separately; secrets are deliberately absent. Run `python3 -m src.news.live_runner --once` only when you intend to use real providers and after configuring the existing quota controls. The bundled original live state remains unchanged, so existing snapshots are not automatically regraded or repopulated as Outlook; newly ingested eligible previews take the new route.
